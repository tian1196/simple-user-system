## 一、架构说明

```text
浏览器 → http://公网IP/
              ↓
         Nginx(:80)
              ↓
    Node(127.0.0.1:3000，systemd 常驻)
              ↓
    /opt/device-ledger/data/ledger.sqlite
```

要点：

1. Node 需要在服务器上**一直运行**（systemd），不是“打包成静态文件”。
2. 前端构建产物由 Node 托管；Nginx 把 `/` 与 `/api` 反代到本机 3000。
3. 生产前端使用相对路径 `/api/v1`，与页面同源，无需在前端写死公网 IP。
4. 设置了 `DATABASE_PATH` 时**不会**自动播种演示账号，需手动创建 owner。

## 三、实操步骤

### 第 0 步：本机 SSH 能登录服务器

```bash
ssh root@115.190.233.106
```

首次确认指纹后输入 root 密码。看到 `[root@... ~]#` 即成功。

> FinalShell / 系统终端均可。一键部署脚本会多次 `scp`/`ssh`，每次都可能要输密码。
> 可选：本机执行 `ssh-copy-id root@115.190.233.106`，之后免密。

### 第 1 步：备份服务器已有数据库

在**已登录的服务器终端**执行：

```bash
install -d -m 0700 /opt/device-ledger/backups
backup_file="/opt/device-ledger/backups/ledger-$(date +%Y%m%d-%H%M%S).sqlite"
if command -v sqlite3 >/dev/null 2>&1; then
  sqlite3 /opt/device-ledger/data/ledger.sqlite ".timeout 5000" ".backup '$backup_file'"
else
  echo "缺少 sqlite3：请改用 deploy/README.md 中的 Node 在线备份命令；禁止直接复制在线主库。" >&2
  exit 1
fi
ls -lh "$backup_file"
echo "备份完成: $backup_file"
```

`deploy.sh` **不会覆盖**已有库文件，但上线前仍建议先备份。

### 第 2 步：本机一键部署（HTTP）

**新开本机终端**（不要占用已登录的 SSH 窗口），进入项目根目录：

```bash
cd "/Users/xuetao/Desktop/AI相关/个人设备台帐/simple-user-system"
DEPLOY_HOST=115.190.233.106 bash scripts/deploy.sh
```

脚本内部 6 步：

1. `pack.sh` 本地构建用户站 `web/site-dist` 和后台 `web/dist`，打包并生成 SHA256
2. 上传到临时目录，校验后解压到临时版本目录
3. 安装 Node 24（`/opt/node24`）
4. `npm ci --omit=dev --ignore-scripts`、创建用户 `deviceledger`、检查已有数据库与候选配置、在线备份、切换版本
5. 安装并启用 `device-ledger.service`（`APP_ORIGINS=http://115.190.233.106`，`COOKIE_SECURE=false`）
6. 安装 Nginx 配置并重启

成功末尾类似：

```text
部署完成
  用户站点：  http://115.190.233.106/
  管理后台：  http://115.190.233.106/admin/
  健康检查：  http://115.190.233.106/api/health
```

### 第 3 步：确认服务状态（服务器）

```bash
systemctl status device-ledger --no-pager
curl -sS http://127.0.0.1:3000/api/health
curl -sS http://127.0.0.1:3000/api/v1/health/ready
nginx -t
```

本机浏览器也可直接打开健康检查 URL。

### 第 4 步：创建后台 owner（线上库不会自动播种）

线上通过 `DATABASE_PATH` 启动时，**不会**创建本地演示账号 `owner / ledger-owner-2026`。
若库中没有 `owner`/`operator`，需手动创建。

先查询：

```bash
export PATH=/opt/node24/bin:$PATH
cd /opt/device-ledger/app
node -e 'const {DatabaseSync}=require("node:sqlite");const db=new DatabaseSync("/opt/device-ledger/data/ledger.sqlite");console.log(db.prepare("SELECT username, role, status FROM users WHERE role IN (?,?)").all("owner","operator"));db.close();'
```

若为空，再执行创建（**FinalShell 请整行复制**，避免多行 heredoc 被挤成一行）：

```bash
export PATH=/opt/node24/bin:$PATH; cd /opt/device-ledger/app; node -e 'const c=require("crypto"),b=require("bcryptjs"),{DatabaseSync}=require("node:sqlite");const db=new DatabaseSync("/opt/device-ledger/data/ledger.sqlite");db.exec("PRAGMA foreign_keys=ON;");if(db.prepare("SELECT COUNT(*) AS n FROM users WHERE role IN (?,?)").get("owner","operator").n>0){console.log("already exists");process.exit(0)}const u="owner",p=c.randomBytes(24).toString("base64url"),now=Date.now(),id=c.randomUUID(),raw=c.randomBytes(8).toString("hex").toUpperCase(),rc="RC-"+raw.slice(0,4)+"-"+raw.slice(4,8)+"-"+raw.slice(8,12)+"-"+raw.slice(12,16),ph=b.hashSync(p,10),rh=c.createHash("sha256").update(rc).digest("hex");db.exec("BEGIN");db.prepare("INSERT INTO users (id,username,role,status,created_at,updated_at,version) VALUES (?,?,?,?,?,?,1)").run(id,u,"owner","active",now,now);db.prepare("INSERT INTO auth_identities (id,user_id,provider,provider_key,password_hash,recovery_code_hash,created_at,updated_at) VALUES (?,?,?,?,?,?,?,?)").run(c.randomUUID(),id,"password",u,ph,rh,now,now);db.exec("COMMIT");db.close();console.log("OK");console.log("user="+u);console.log("pass="+p);console.log("recovery="+rc);'
```

登录页填写：

| 字段 | 值 |
| --- | --- |
| 用户名 | `owner` |
| 密码 | 创建命令生成的随机密码，仅输出一次，请安全保存 |
| 图形验证码 | 登录页图片中的 4 位字符（不区分大小写，可点击刷新） |

登录后请尽快在「系统账号」中修改为强密码，并妥善保存恢复码。

## 五、常见问题

| 现象 | 处理 |
| --- | --- |
| 本机 `Permission denied (publickey,...)` | 用密码登录，或配置 `ssh-copy-id`；确认用户为 `root` |
| FinalShell 粘贴多行脚本无响应 | 多行 heredoc 易被挤成一行；改用本文单行 `node -e` |
| `no such column: "owner"` | SQLite 把双引号当标识符；字符串用绑定参数 `?` |
| `db.transaction is not a function` | `node:sqlite` 的 `DatabaseSync` 无 better-sqlite3 风格 `transaction`；用 `BEGIN`/`COMMIT` |
| 后台写操作 403「请求来源不正确」 | 检查 `APP_ORIGINS` 是否含浏览器实际地址（如 `http://115.190.233.106`） |
| 登录后频繁掉登录 | HTTP 下 `COOKIE_SECURE` 必须为 `false` |
| 页面 502 | `systemctl status device-ledger`，确认监听 `127.0.0.1:3000` |
| 想启用 HTTPS | 需要域名 + 证书；`DEPLOY_DOMAIN=域名 bash scripts/deploy.sh --https`，并设 `COOKIE_SECURE=true` |

## 六、安全提醒

- 不要把本机 `data/ledger.sqlite`、`.env`、`node_modules` 上传覆盖服务器。
- 默认初始密码仅用于首次进入，登录后立即修改。
- 无域名阶段仅建议内测；正式对外请上 HTTPS。
- 定期对 `/opt/device-ledger/data/ledger.sqlite` 做 `sqlite3 .backup`。
